# RED SEA: тестовая сборка с исправлениями — как прошить через браузер

Сборка для проверки на устройстве. В ней исправления по итогам ревью и замеров на железе (ветка
`rebuilt` в github.com/zemuro/RedSea-rebuilt, коммит `2565fc1`). Код по-прежнему в одном файле
`REDSEA.ino`; каждое изменение — отдельный коммит с тестом и замером «до/после».

## Файлы

| Файл | Что это |
|---|---|
| `redsea-rebuilt-2026-10-05-2565fc1.bin` | сборка с исправлениями |
| `redsea-original-a424db2.bin` | исходная прошивка (коммит `a424db2`), собранная тем же способом, — чтобы сравнивать «до» и «после» на одном устройстве |

Каждый файл — полный образ (загрузчик, таблица разделов и прошивка), пишется целиком с адреса `0x0`.

## Прошивка через браузер

Нужен Chrome или Edge на компьютере: браузер работает с USB-портом через Web Serial. Firefox и
Safari его не поддерживают. Ставить ничего не нужно.

1. Подключи устройство кабелем USB-C к компьютеру. Закрой программы, которые могут держать его
   порт (Arduino IDE, монитор порта PlatformIO).
2. Открой **https://espressif.github.io/esptool-js/** — это официальный веб-прошивальщик Espressif.
3. В разделе **Program**:
   - **Baudrate** — оставь 921600;
   - нажми **Connect** и выбери в списке порт устройства — **USB JTAG/serial debug unit** (или похожий
     с «ESP32-C3» / «USB Serial Device»);
   - после подключения в журнале появится строка с `ESP32-C3`.
4. В таблице файлов, в первой строке: **Flash Address** — `0x0` (по умолчанию там может стоять
   другой адрес — замени), справа выбери файл `redsea-rebuilt-….bin`. Лишние строки, если есть,
   удали. **Flash Mode**, **Flash Frequency** и **Flash Size** оставь `keep` — параметры флеша уже
   записаны в образ.
5. Нажми **Program**. Запись занимает несколько секунд; в конце — «Leaving…».
6. Нажми **Disconnect**, затем отключи и снова подключи USB (или нажми RESET на модуле).
   На экране — «RED SEA / BOOTING…», затем главная страница.

**Если порт не подключается:** отключи USB, зажми кнопку **BOOT** на модуле ESP32-C3, подключи
USB, отпусти BOOT и повтори с шага 3.

**Вернуть исходную прошивку** — то же самое с файлом `redsea-original-a424db2.bin`.

## Настройки и паттерн

Прошивка с адреса `0x0` раздел настроек (NVS) не трогает: номера CC, диапазоны, параметры движков и
паттерн секвенсора сохранятся. BPM теперь хранится 16-битным (до 300); прежнее значение подхватится.

Если после прошивки поведение странное — нажми **Erase Flash** (там же, после Connect), затем снова
**Program**. Это сбросит все настройки и паттерн к умолчаниям.

## Что изменилось и что послушать

Полный список с цифрами — `docs/REVIEW.md` в репозитории. Коротко:

**Тайминг.** Такты, MIDI-вход и отправка вынесены из `loop()` в отдельную задачу FreeRTOS с высоким
приоритетом, которая просыпается каждые 0,5 мс и точно к моменту такта. Экран рисуется и передаётся
по I²C в фоне. Опоздание внутреннего такта — до 0,6 мс (было до 23 мс, а через 10 минут работы темп
проседал на 25 % на 120 BPM и на 66 % на 240 BPM из-за медленного синуса в анимациях). Нажатия PLAY
(анимация FREEZE) такты больше не останавливают.

**Clock наружу.** При внутреннем темпе двойной TAP отправляет Start, затем Clock на каждом такте,
повторный двойной TAP — Stop. Ведомый инструмент должен идти в темпе RED SEA.

**Секвенсор.**
- Первым после старта звучит шаг 1 (раньше — шаг 2, через 6 тактов).
- Note Off — как ты описал: нота звучит до следующей активной ноты, через пустые шаги; сначала Off,
  потом On; та же нота перезапускается. По Stop — Note Off и All Notes Off (CC 123); при входе в
  BYPASS и при смене канала нота гаснет.
- Clock из DAW без Start плюс запуск двойным TAP больше не удваивает темп; запуск двойным TAP под
  внешний Clock — со следующей доли.
- RAIN, SNOW и RFLCT после Stop → Start работают сразу (раньше молчали столько, сколько длился
  прошлый прогон).

**Прочее.** BPM до 300; сохраняются номера CC всех четырёх параметров (раньше — только того, что под
курсором); энкодер не теряет щелчки при быстром вращении; MIDI Learn отменяется любой кнопкой; в FOG
нет случайного CC перед значением LFO, и LFO отправляет CC только при изменении; анимация после выхода
из FREEZE продолжается с того же места.

## Два вопроса по этой сборке

1. **Clock в BYPASS.** По MANUAL BYPASS глушит весь выход. Сейчас Clock, Start и Stop в BYPASS
   проходят — иначе ведомые инструменты теряли бы синхронизацию. Оставить так или глушить и их?
2. **Сохранение во время игры.** Пока идёт транспорт, настройки во флеш не пишутся (каждая запись
   останавливала процессор на 3–20 мс), а сохраняются после остановки. Если выключить питание посреди
   игры, правки, сделанные во время игры, не сохранятся. Так приемлемо?
