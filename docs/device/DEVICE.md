# Устройство: железо ESPidi

Сводка того, что известно о плате, на которой работает RED SEA. Источники: README и HARDWARE.MD
проекта ESPidi (автор железа — Евгений, github.com/EugeneCarlo/ESPidi), трассировка Gerber-файлов,
замеры на устройстве пользователя в проекте ESPidi-rebuilt (октябрь 2026).

## Контроллер

| | |
|---|---|
| Модуль | ESP32-C3 Super Mini |
| Ядро | одно, RISC-V 32-bit, 160 МГц (`F_CPU`) |
| ОЗУ | 400 КБ SRAM (под приложение ~320 КБ), PSRAM нет |
| Флеш | 4 МБ; PlatformIO пишет в режиме DIO, 80 МГц |
| Беспроводное | Wi-Fi, BLE 5.0 (Bluetooth Classic нет) |
| USB | встроенный USB Serial/JTAG, VID `0x303A`; на ПК — «USB Serial Device» |
| Кнопки на плате | BOOT (держать при подключении USB, если устройство не прошивается) и RESET |

**Одно ядро.** Всё — основной цикл Arduino (`loopTask`, приоритет 1), обработчики прерываний,
задачи FreeRTOS, `esp_timer` (задача с приоритетом 22) — делит одно ядро. Долгая операция в `loop()`
останавливает всё, что не вынесено в задачу с более высоким приоритетом.

**Запись во флеш останавливает процессор.** На время стирания и записи сектора (NVS, EEPROM,
Preferences, LittleFS) кэш флеша отключается, и любой код не из IRAM стоит — включая задачи с высоким
приоритетом. На устройстве измерено 3–18 мс на одну запись настроек.

## Выводы

| GPIO | Назначение | Режим |
|---:|---|---|
| 1 | кнопка PLAY | `INPUT_PULLUP`, нажатие = LOW |
| 2 | кнопка TAP | `INPUT_PULLUP`, нажатие = LOW |
| 3 | кнопка PAGE (в коде ESPidi — `BTN_L_R`) | `INPUT_PULLUP`, нажатие = LOW |
| 4 | кнопка энкодера | `INPUT_PULLUP`, нажатие = LOW |
| 5 | энкодер, фаза B (в ESPidi `ENC_B = 5`) | `INPUT_PULLUP` |
| 6 | энкодер, фаза A (в ESPidi `ENC_A = 6`) | `INPUT_PULLUP` |
| 7 | MIDI IN (UART RX) | |
| 8 | OLED SDA | I²C |
| 9 | OLED SCL | I²C |
| 10 | MIDI OUT (UART TX) | |
| 0 и ещё два | свободны, с ограничениями ESP32-C3 (strapping) — см. даташит | |

**Внимание:** в RED SEA `ENC_A = 5`, `ENC_B = 6` — наоборот относительно ESPidi. Это меняет
направление вращения, если таблица квадратуры не компенсирует. Проверить на устройстве.

**Надписи на панели:** кнопки PLAY, TAP, PAGE; между ними напечатаны REC (между PLAY и TAP) и STEP
(между TAP и PAGE) — это сочетания из прошивки ESPidi. В RED SEA у кнопок своя логика жестов.

**Кнопки — с RC-фильтром** (трассировка Gerber `ESPIDI-BLANK`, 2026-10-04). Каждая кнопка (PLAY → GPIO1,
TAP → GPIO2, PAGE → GPIO3) — SMD на верхней стороне: одна площадка на земле, другая через переходное
отверстие и **резистор 1 кОм** идёт к выводу, а от вывода на землю стоит **конденсатор 0,1 мкФ**
(постоянная времени 0,1 мс — дребезг это почти не гасит, программный антидребезг нужен). Пути для TAP —
`tap_top.png` (вид сверху) и `tap_bottom.png` (вид снизу, зеркально). Ориентация модуля подтверждена по
дисплею: D → GPIO8, C → GPIO9, «+» → 3V3, «−» → GND; GPIO0, 20 и 21 не подключены.

**Аккумулятор 10440 лежит снизу прямо за экраном и кнопками**; под ним проходит переходное отверстие от
площадки TAP, под кнопками — дорожка 5 V. 2026-10-04 при нажатиях TAP устройство дважды сбрасывалось
(второй раз пропало с USB, экран погас и сильно нагрелся); прошивка нажатия TAP не увидела (GPIO2 не
опускался в LOW). Сама кнопка TAP 3,3 V ↔ GND не замыкает. Подозрение — механика: нажатие продавливает
плату к аккумулятору или его выводам. Проверить изоляцию аккумулятора и низ платы под ним.

## Энкодер

EC11 с кнопкой. Квадратурный: 4 перехода на один щелчок. В ESPidi обрабатывается прерываниями
`CHANGE` на обеих фазах по таблице Грея. Аппаратного антидребезга кнопок не обнаружено (ESPidi
использует программный, 30 мс).

## Экран

| | |
|---|---|
| Контроллер | SSD1306, 128×32, 0,91″ |
| Цвет | у пользователя — белый; встречаются голубые и жёлтые |
| Адрес I²C | `0x3C` (у некоторых модулей `0x3D`) |
| Шина | I²C, SDA 8, SCL 9; по даташиту SSD1306 — до 400 кГц |
| Буфер | 512 байт: 4 страницы по 128 байт, каждая страница — полоса 8 строк пикселей |

Замеры на 400 кГц: полный кадр (`display.display()`, 512 байт) ≈ 14 мс; одна страница ≈ 3,9 мс.
Adafruit SSD1306 поднимает шину до 400 кГц на время своих передач и после возвращает 100 кГц — если
писать на дисплей в обход библиотеки, частоту нужно выставлять самому (`Wire.setClock(400000)`).
Отправка только изменившихся страниц (сравнение с теневой копией, окна `PAGEADDR`/`COLUMNADDR`)
проверена на устройстве пользователя визуально — артефактов нет.

## MIDI

| | |
|---|---|
| UART | `Serial1` (UART1), 31 250 бод, 8N1 |
| Время на проводе | 0,32 мс на байт; 3-байтное сообщение ≈ 0,96 мс |
| MIDI Clock | 24 импульса на четверть; при 120 BPM интервал 20,83 мс |
| Вход | через оптрон 6N137, с диодным мостом — полярность TRS неважна |
| Выход | OUT_5 = GPIO10 (TX) через R7 10 Ом; OUT_4 = +3,3 В через R8 10 Ом |
| Разъёмы | DIN-5 или TRS 3,5 мм (общие посадочные места, на каждое — один из двух) |

Ориентиры по стоимости операций на проводе: 128 NoteOff ≈ 120 мс; CC 123 на все 16 каналов ≈ 15 мс.
Пока такие пачки уходят, а код ждёт освобождения UART, такты стоят.

### TRS: перемычки типа выхода

Тип TRS выхода (A или B) задаётся двумя трёхконтактными перемычками «TYPE MIDI OUT» на нижней стороне
платы, рядом с MIDI_OUT. Обе перемычки замыкаются в одну сторону: контакты ближе к краю платы — Type A,
дальше от края (к 6N137) — Type B. **Никогда не замыкать все три контакта**: это замыкает +3,3 В на TX.
Незапаянные перемычки = MIDI OUT молчит.

### Устройство пользователя

- Разъёмы TRS (ST-021); перемычки выхода запаяны на **Type B**.
- К ПК подключено USB-MIDI кабелем с DIN-штекерами через переходники TRS → DIN (оба проверены как
  Type B; у одного не подключён экран — его лучше на вход ESPidi).
- COM-порт устройства — **COM5** (COM3 и COM4 — последовательные порты Bluetooth, не устройство).
- MIDI-порты ПК — `USB2.0-MIDI` (вход и выход); `MIDIOUT2 (USB2.0-MIDI)` — фантомный.
- Если MIDI OUT молчит при живом входе, сначала проверять кабель и переходники, затем прошивку.
- 2026-10-05 вход MIDI IN начал принимать искажённые байты (`f8 fa fc …` → `de 8e 46 …`, половина
  потеряна, одинаково при повторе) — после переподключения штекера и переходника всё стало точно.
  Плохой контакт TRS/переходника выглядит как сбитая скорость, а не как редкие помехи. Проверка:
  команда стенда `rxlog` после отправки известных байтов.

## Питание

USB-C; встроенный аккумулятор 10440 (по README ESPidi).

## Флеш-память и разметка

Таблица разделов Arduino-ESP32 по умолчанию (её использует PlatformIO для `esp32-c3-devkitm-1`):

| Раздел | Смещение | Размер | Кто использует |
|---|---|---|---|
| nvs | `0x9000` | 20 КБ | ESPidi (EEPROM-эмуляция), RED SEA (`Preferences`, пространство `redsea`) |
| otadata | `0xE000` | 8 КБ | загрузчик |
| app0 | `0x10000` | 1,25 МБ | прошивка |
| app1 | `0x150000` | 1,25 МБ | не используется |
| spiffs | `0x290000` | 1,4 МБ | ESPidi — LittleFS (паттерны, песни); RED SEA — не использует |
| coredump | `0x3F0000` | 64 КБ | |

Прошивка одним файлом: загрузчик `0x0`, таблица разделов `0x8000`, `boot_app0.bin` `0xE000`,
приложение `0x10000`. Перепрошивка приложения **не стирает** NVS и LittleFS: настройки прошлой прошивки
остаются. При переключении между прошивками для чистых замеров стирать флеш целиком
(`pio run -t erase` или `esptool.py --chip esp32c3 erase_flash`).

## Программная платформа

- PlatformIO `espressif32@6.13.0` → Arduino-ESP32 2.0.17 (ESP-IDF 4.4.7), FreeRTOS.
- Библиотеки, проверенные на этом железе: Adafruit SSD1306 2.5.17, Adafruit GFX 1.12.6,
  Adafruit BusIO 1.17.4, MIDI Library 5.0.2 (в ESPidi; RED SEA разбирает MIDI сам).
- USB-консоль (`Serial`) работает через HWCDC, только если собрано с `-DARDUINO_USB_MODE=1
  -DARDUINO_USB_CDC_ON_BOOT=1` (так собирается тестовое окружение).
